# Local code search (RAG) + MCP server for agents

> **For the implementer (Cursor):** apply the tasks in order, one commit per task, tests first where a task has logic. Claude (Opus) reviews every commit on Stefano's Mac and decides the next step. Stop at the **STOP** marks and wait.

**Goal:**
- The app indexes a project (code + wiki) with a local embedding model that the person picks from a catalog.
- A standalone MCP server, `codebase-wiki-mcp`, lets any agent (Claude Code, Codex, Cursor, Antigravity) search that index.
- The agent then uses `search_code` for *where/how* questions and the wiki for *status, decisions and why*.

**Why:** the wiki answers what the project is and why. It does not answer "where is the debounce of the watcher", and grepping a big repo burns the agent's context. A local index answers that in one call, without sending code anywhere.

**What does not change:**
- The plugin (Codebase Wiki LLM) stays separate and works without the app.
- The wiki stays in the project.
- Only the derived index lives in the app data folder, and it can always be rebuilt.

**Branch:** `feat/rag-mcp`, created from `app/hardening` (commit `2e8043c` or later). Push it after every commit.

## Decisions (Stefano, 2026-11-11)

| # | Decision | Why |
|---|---|---|
| R1 | **Standalone stdio MCP server** (`codebase-wiki-mcp serve`), works with the app closed | every harness speaks MCP over stdio. The app is only the control panel |
| R2 | **Curated model catalog** plus an advanced Hugging Face search, run in-process with ONNX (`fastembed`) | no Python and no Ollama for the person to install. Small int8 models are good enough for code |
| R3 | **Index in the app data folder**, never in the repo | nothing to `.gitignore`, nothing to commit by mistake. The wiki stays in the project |
| R4 | **Routing** comes from the MCP `instructions` plus one conditional sentence in the plugin rule | the plugin stays usable alone. The sentence is harmless when the tool is absent |
| R5 | **One writer:** only `codebase-wiki-mcp index` writes an index, and only the app launches it. `serve` only reads and reports staleness | no locks between harness sessions. A killed indexing run leaves a consistent DB, because each file is one transaction |
| R6 | The app links `rag-core` **without** the `embed` feature, and runs the binary as a sidecar for indexing, model download and preview search | the app does not carry ONNX Runtime twice, and a model crash cannot take the window down |
| R7 | Model download is our own code (`ureq`), never fastembed's downloader | we need progress lines, a fixed folder and checksums. The server must never download |

## Layout

```
crates/wiki-core    + pub: read_private_terms, content_has_forbidden_term, is_private_terms_name,
                      parse_excluded_globs(schema_md), glob_match (fnmatch, * crosses /)
crates/rag-core     paths · repo_id · catalog · files · chunk · store · search   [feature "embed" = fastembed]
crates/wiki-mcp     bin codebase-wiki-mcp: serve | index | search | status | models list|pull
src-tauri           rag commands (status, start index, cancel, models, preview, connect) over the sidecar
src/views/Ricerca   new section "Ricerca"
```

**Data folder:** `rag_core::paths::data_dir()` is the only definition, shared by the app and the binary. It is `dirs::data_local_dir()/com.codebasewiki.app/rag`, overridden by `CODEBASE_WIKI_DATA_DIR`. Inside:

```
config.json                  { "model": "multilingual-e5-small" }
models/<id>/                 model.onnx, tokenizer.json, config.json, special_tokens_map.json, tokenizer_config.json, .complete
indexes/<repo_id>.sqlite     one DB per repo (WAL)
bin/codebase-wiki-mcp[.exe]  stable path written in harness configs
```

**`repo_id`:** the first 16 hex characters of `sha256(canonical git toplevel)`, lower-cased on macOS and Windows. The repo is resolved in this order: `--repo <path>`, then `CODEBASE_WIKI_REPO`, then the current directory walked up to the git root. Harnesses start MCP servers in the project folder, so the third rule is the normal path.

**Progress protocol** (binary → app, one JSON object per stdout line, for `index` and `models pull`):

```json
{"event":"phase","phase":"wiki","total":120}
{"event":"progress","phase":"wiki","done":40,"total":120}
{"event":"phase","phase":"code","total":2300}
{"event":"done","files":2420,"chunks":18311,"skipped_private":3,"ms":81234}
{"event":"error","message":"Indice: .private-terms illeggibile, indicizzazione fermata"}
```

Download progress uses `{"event":"download","file":"model.onnx","done":bytes,"total":bytes}`. Human text goes to stderr. The exit code is 0 on `done` and non-zero on `error`.

### Task B3: Chunking and the privacy filter

`chunk::chunk_file(rel_path, text, source) -> Vec<Chunk { start_line, end_line, text }>`:

- **Code:** use `text-splitter` `CodeSplitter` with the tree-sitter language picked by extension (rs, ts, tsx, js, jsx, mjs, cjs, py, go). Other text files use `TextSplitter`. The target is about **1500 characters** per chunk, with a range of 800..1800.
- **Wiki and other Markdown:** use `MarkdownSplitter` with the same size, so chunks break on headings.
- **Line numbers:** compute `start_line` and `end_line` (1-based, inclusive) from each chunk's byte offset (`chunk_indices`).
- **Embedded text:** `"{rel_path}\n{nearest heading or first line}\n{chunk}"`, so a path query finds the file. Only the plain chunk text is stored for display.

**Privacy (fail-closed):**
- `index` reads `.private-terms` with `wiki_core::read_private_terms(wiki_dir)`. If it returns `Err`, stop with a `{"event":"error"}` and write nothing.
- A chunk where `content_has_forbidden_term` is true is dropped and counted in `skipped_private`. The term itself is never printed.
- Store `terms_hash = sha256(terms file)` in `meta`. If it changes, the next `index` rebuilds the whole DB.

**Tests:**
- a Rust file with two functions gives two chunks with correct line ranges;
- a Markdown file breaks on `##`;
- a chunk containing a private term is dropped and the count is 1;
- an unreadable `.private-terms` (a symlink to a file) returns `Err` and no DB is created.

### Task B4: Store and hybrid search

`store::Store::open(path, dims, model_id)` (rusqlite `bundled`, WAL, sqlite-vec loaded with `sqlite3_auto_extension` or `load`):

```sql
meta(key TEXT PRIMARY KEY, value TEXT)            -- model_id, dims, indexed_head, terms_hash, schema_version=1
files(id INTEGER PRIMARY KEY, path TEXT UNIQUE, source TEXT, size INTEGER, mtime INTEGER, sha256 TEXT)
chunks(id INTEGER PRIMARY KEY, file_id INTEGER REFERENCES files(id) ON DELETE CASCADE,
       start_line INTEGER, end_line INTEGER, text TEXT)
chunks_fts USING fts5(text, content='chunks', content_rowid='id', tokenize='unicode61 remove_diacritics 2')
vec_code USING vec0(embedding float[DIMS] distance_metric=cosine)   -- rowid = chunks.id
vec_wiki USING vec0(embedding float[DIMS] distance_metric=cosine)
```

- If `model_id` or `dims` differ from `meta`, delete the file and create a new DB.
- `replace_file(entry, sha, chunks, vectors)` runs in **one transaction**: delete the old chunks, FTS rows and vectors, then insert the new ones. `remove_missing(paths_now)` drops files that no longer exist.
- `search(query_vec, query_text, source, k, path_glob) -> Vec<Hit { path, start_line, end_line, source, score, text }>`:
  - take the top 50 from FTS5 (`bm25`) and the top 50 from the vector table for that source;
  - fuse them with **RRF**: `score = Σ 1/(60 + rank)`;
  - filter by `wiki_core::glob_match(path_glob, path)` when given;
  - return the top `k`.
  - Escape the FTS query: quote each token, and drop FTS operators.

**Plan B** (only if B0 found that sqlite-vec does not build on a runner): store vectors as a BLOB column in `chunks`, and scan in Rust (dot product on normalized vectors). This is fine up to about 200k chunks. Same API.

**Tests, with fake 4-dim vectors and no model:**
- RRF puts a doc ranked 1 in both lists first;
- an FTS-only hit still appears;
- `path_glob` filters results;
- `replace_file` twice leaves one copy;
- a model change rebuilds the DB.

### Task B7: `serve`, the MCP server

`rmcp` server, stdio transport, name `codebase-wiki`, version = crate version.

**`instructions`:**

> Local search over this repository's code and its Codebase Wiki. Use `search_code` for *where/how* questions (where is X defined, how does Y work, what calls Z) before grepping. Use the wiki pages for status, decisions, risks and *why*. Results marked `stale: true` changed after indexing: re-read those lines from disk before relying on them.

**Tools (JSON schema via rmcp macros):**

| tool | params | returns |
|---|---|---|
| `search_code` | `query: string`, `k?: int = 8 (max 20)`, `path_glob?: string` | header line + hits |
| `search_wiki` | `query: string`, `k?: int = 5 (max 20)` | header line + hits |
| `index_status` | none | the `status --json` object |

- **Each hit:** `{path, start_line, end_line, source, score, stale, snippet}`. The snippet is at most 40 lines.
- **`stale`:** the file's `mtime` or `size` now differs from the index.
- **Header:** `index @<short indexed_head> · HEAD @<short head> · N file cambiati dall'indice`.
- **Model loading:** the model is loaded at the first search (`OnceCell`), not at startup.
- **Privacy:** results are re-checked against the **current** `.private-terms`. A hit with a forbidden term is dropped, and an unreadable terms file returns an error and no results.
- **Missing index or model:** return a tool error, `Indice assente per questo repo: apri Codebase Wiki → Ricerca → Indicizza`. Never index and never download from `serve`.
- **Logging:** stderr only; stdout is the protocol.
